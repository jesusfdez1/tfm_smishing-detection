# MetaSMS Dataset Data Dictionary

This document provides the formal description of all variables, categories, and coding schemes that make up the final meta-dataset `metasms_v1_enriched.csv`. All information contained in the dataset follows the standardized rules and data dictionaries below.

## General Column Structure

| Column | Description | Data Type / Possible Values |
|---------|-------------|--------------------------------|
| **`message_id`** | Unique message identifier (e.g., `msg_1a2b3c4d`). | `String (Hash)` |
| **`canonical_label`** | Definitive unified label. | `Category` (See section 3) |
| **`text_raw`** | Raw unaltered original message as it comes from the source (with possible obfuscations and PII information). | `String` |
| **`text`** | Processed and normalized message after mitigating obfuscations, but keeping real links and phones (processed text). | `String` |
| **`text_anonymized`** | Normalized message after additionally applying privacy masking (PII replaced by tokens). | `String` |
| **`reference`** | Name of the dataset or source it comes from. | `Category` (See section 4) |
| **`source_id`** | Original message ID in its source dataset. | `String` or Empty |
| **`original_label`** | The original label the message had at its source. | `String` |
| **`label_mapping_rule`** | Rule applied to transform the original label. | `String` |
| **`is_ai_generated`** | Indicates if the message was synthetically generated by Artificial Intelligence (0 or 1). | `Boolean (0 or 1)` |
| **`timestamp_original`** | Original date and time of the message (if available). | `String (ISO 8601)` or Empty |
| **`license`** | Usage license of the original message/dataset. | `String` |
| **`language`** | Main detected language. | `Category` (See section 5) |
| **`language_confidence`** | Confidence level of the language detection. | `Float (0.0 - 1.0)` or `"LLM"` |
| **`anonymization_status`** | Anonymization status of the text. | `Category` (See section 2) |
| **`llm_model`** | The model used to enrich the row. | `String` (e.g., `Qwen/Qwen3.5-35B-A3B-GPTQ-Int4`) |
| **`prompt_version`** | The prompt version used in the LLM. | `String` |
| **`llm_annotation_date`** | Date the LLM processed this row. | `String (ISO 8601)` |
| **`theme`** | Main category or intent of the message. | `Category` (See section 6) |
| **`urgency_level`** | Urgency level conveyed by the message. | `Category` (See section 7) |
| **`whois_domain`** | Domain extracted from the link (if it exists) after Whois resolution. | `String` (or `"ERROR"`) or Empty |
| **`whois_tld`** | Top Level Domain extracted from the domain. | `String` (or `"ERROR"`) or Empty |
| **`whois_age_days`** | Domain age in days extracted via Whois. | `Integer` or Empty |
| **`whois_hidden`** | Indicates if the Whois details of the domain are hidden/private (1 or 0). | `Boolean (0 or 1)` or Empty |
| **`whois_country`** | Domain registration country obtained via Whois. | `String` or Empty |

## Values and Categories Dictionaries

### 1. Boolean Variables
Several columns use a standardized boolean format with integer values (0 and 1) to facilitate processing in Machine Learning:
- **`0`**: False (Does not apply)
- **`1`**: True (Applies)

*Applies to columns: `whois_hidden`, `is_ai_generated`.*

### 2. `anonymization_status`
Defines what type of privacy processing the message has received:
- **`raw`**: The message has not undergone any changes (contains no personally identifiable information or no anonymization was applied).
- **`anonymized`**: The message contained PII and was anonymized by our script (e.g., replacing links with `[URL]`).
- **`pre_anonymized`**: The message already came with anonymization tokens applied in the source dataset (e.g., `<URL>`).

### 3. `canonical_label` (Main Classification)
It is the unified label that Machine Learning models must predict (the dependent target variable):
- **`ham`**: Legitimate, harmless, and safe message (e.g., real purchase confirmation, messages between family members).
- **`spam`**: Unwanted commercial promotional message but not malicious, criminal, or fraudulent (e.g., aggressive insurance advertising).
- **`smishing`**: Fraudulent or malicious message (SMS phishing) designed to steal credentials, deceive financially, or infect the device.

### 4. `reference` (Source Datasets)
Indicates which original dataset the row comes from. Possible values extracted in the ETL pipeline:
- `agarwal_2025`
- `exais_sms`
- `hosseinpour_2025`
- `kaggle_phishing`
- `kaggle_spam_ham`
- `malicious_benign_sms_mms`
- `mimics_3500`
- `mishra_extended`
- `mishra_soni_2022`
- `nus_sms`
- `smishing_4c`
- `spanish_spam_ham`
- `uci_sms_spam`

### 5. `language` (ISO 639-1 Languages)
Languages are standardized using the international ISO 639-1 standard (two lowercase letters). Most common examples in our dataset:
- `en` (English)
- `es` (Spanish)
- `fr` (French)
- `pt` (Portuguese)
- `it` (Italian)
- `de` (German)
- `nl` (Dutch)
- `unknown` (Could not be detected, unintelligible text, too short or null)

### 6. `theme` (Intents and Themes)
Classifies the main purpose or theme of the message. The LLM obligatorily categorizes the message into exactly one of these 14 categories (closed taxonomy) for the entire dataset:
- **`personal`**: Casual conversation, greetings, questions between people (e.g., "What's up?").
- **`family_emergency`**: Impersonation of relatives claiming broken phones or urgently requesting money (e.g., "Hi mom, this is my new number").
- **`banking`**: Banks, transfers, credit cards, cryptocurrencies.
- **`delivery`**: Parcels, post office, customs, shipment tracking.
- **`account_security`**: Account locks, suspicious logins, identity verification.
- **`tech_support`**: Fraudulent technical support, fake virus or device infection alerts.
- **`promotion`**: Prizes, lotteries, discounts, commercial offers.
- **`survey`**: Requests to participate in surveys, questionnaires, or market research.
- **`government`**: Traffic fines, taxes, public administration notifications.
- **`job_offer`**: Recruitment offers, fake employment, easy money making.
- **`dating_adult`**: Dating, sexual content, adult contacts.
- **`subscription`**: Premium SMS services, horoscopes, ringtones.
- **`service_alert`**: Medical appointments, supply cuts (electricity/water), service reminders.
- **`unknown`**: Cannot be determined or makes no sense.

### 7. `urgency_level` (Urgency Level)
Represents the temporary psychological pressure the message tries to exert on the user, using a closed taxonomy of 4 levels:
- **`none`**: No urgency, normal or informative chat.
- **`low`**: Informative, requires action but no time pressure.
- **`medium`**: Requires attention soon (e.g., "reply when you can", "your package will arrive tomorrow").
- **`high`**: Immediate action required. Uses threatening language, fear, or very short time limits (e.g., "your account will be locked in 1 hour", "click now or lose the prize").

## Annex: Master Prompt (LLM)

To ensure reproducibility and transparency in research (traceability of the `prompt_version` field), the exact system prompt (**`v1.0-local`** version) used to extract the `theme`, `urgency_level` and `language` features via Zero-Shot Learning and Guided JSON Decoding (optimizing latency by removing co-think explanations) is shown below:

```text
You are an expert cybersecurity analyst annotating SMS messages for a machine learning dataset.

Analyze the semantic meaning and return a JSON object with EXACTLY these keys:
- "theme": strictly one of: personal, family_emergency, banking, delivery, account_security, tech_support, promotion, survey, government, job_offer, dating_adult, subscription, service_alert, unknown
- "urgency_level": strictly one of: none, low, medium, high
- "language": 2-letter ISO 639-1 code (e.g., "en", "es", "fr")

Theme definitions:
- personal: Casual conversation, greetings, family matters.
- family_emergency: Fake relatives asking for money ("Hi mom, new number").
- banking: Banks, transfers, cards, crypto, financial alerts.
- delivery: Packages, post office, customs, shipping.
- account_security: Account locks, suspicious logins, OTP codes.
- tech_support: Fake tech support, virus alerts.
- promotion: Prizes, lotteries, discounts, aggressive offers.
- survey: Requests to complete surveys or feedback.
- government: Traffic fines, taxes, public administration.
- job_offer: Recruitment, work from home, easy money scams.
- dating_adult: Dating, sexual content, adult contacts.
- subscription: Premium SMS, horoscopes, ringtones, paid services.
- service_alert: Medical appointments, utility bills, carrier reminders.
- unknown: Unreadable or doesn't fit elsewhere.

Urgency definitions:
- none: No urgency. Normal chat or passive info.
- low: Informative, future action, no time pressure.
- medium: Attention soon ("reply when you can", "arrives tomorrow").
- high: Immediate action. Psychological pressure, threats, short deadlines.

Return ONLY the raw JSON object. No markdown, no explanations.
```
